**Goal:** 为 v0.4 交付三件事，并完成发布战役的全部准备工作：
1. **D2 统计与回顾面板**：把用户已经积累、但「只存在于 30 条文本日记里」的专注历史 [F10]，变成一眼可回看的数字层——今日/本周/本月/累计、一起度过的时间、图鉴完成度、当前成长阶段。全部纯本地计算，不新增持久化字段、不新增上传行为。
2. **D3 存档导出/导入安全网**：让「图鉴与总时长」这份本机唯一副本的资产 [F11] 可以一键备份与恢复，导出→导入往返无损。

成功定义（沿用分析文档 5.1）：统计数字与日记条目一致性有测试；导出导入 100% 往返无损；统计文案过「无压力」审查（无断签渲染、无惩罚性表述）；发布物料三件齐备。

**Architecture:** 改动面收敛在既有架构内，不引入新框架、新依赖、新数据通道：

- **Go 后端（state.go）**：统计派生全部在 `snapshotLocked` 路径扩展——今日重算逻辑 [C1] 已确立「派生数据每次快照实时算、不落盘」的模式，周/月/天数聚合是同一函数的日期前缀参数化（已由技术依据确认 [T1][T5]）。前端 `apply()` 每次收到完整 Snapshot 整体 render，新增面板直接消费同一 Snapshot，无需新数据通道 [T2]。

- **无新持久化字段、无新 RPC 频道之外的任何网络行为。**

## 七、D2 统计与回顾面板

### 7.1 数据模型：三分类明细

| 指标 | 来源 | 分类 | 是否持久化 |
|-|-|-|-|
| 今日专注分钟/轮 | TodaySecs/TodayRounds，snapshotLocked 实时重算（含进行中会话） | 现成，已在上屏 [C1] | 否（现状即不落盘） |
| 累计专注分钟/轮 | TotalSecs / Completed 持久字段 | 现成 [C3] | 是（既有字段，不动） |
| 本周/本月专注分钟/轮 | Records 按日期聚合（照 C1 模式换周/月范围） | 需 records 聚合 | 否，派生 |
| 一起度过的时间（天数） | Records 的日期去重计数 | 需 records 聚合 | 否，派生 |
| 本周有专注的天数 | Records 聚合，限本周范围 | 需 records 聚合 | 否，派生 |
| 图鉴完成度 x/15 | len(Visitors) / 15（15 种硬编码）[C4] | 现成数据，新展示 | 既有 |
| 最近到访的朋友 | Visitors 的 Date + Visits | 现成 [C4]，图鉴已显示「来过 N 次」 | 既有 |
| 当前称号 + 下一档距离 | Completed 分档规则（<3 初生 / <12 萌芽 / <24 繁盛 / ≥24 小小绿洲）[C5] | 现成规则，新展示 | 既有 |
| 植物状态 | plantBed：株数 = min(8, 1+floor((completed−1)/3))，每株三阶 [C6] | 现成规则，新展示 | 既有 |

**需新增派生**的只有三处：周/月聚合、天数聚合、下一档距离计算——全部是展示层派生，通过 snapshot 下发，前端零聚合逻辑。聚合放 Go 后端 `snapshotLocked` 而非 JS（TodaySecs/TodayRounds 即该模式 [C1][T5]）。records 每条仅 5 字段（id/task/seconds/completed/date，只存整数秒、date 为写入时刻 [T1]）——「从几点到几点」「本轮计划多久」无字段可算，不在面板范围；天数 = records 的日期去重计数，受 1000 条截断约束（口径见 7.2）。

### 7.2 已知口径限制（诚实标注，不掩盖）

Records 只保留最近 1000 条（新→旧 prepend 截断）[C2]：**「一起度过 N 天」是留存记录范围内的口径**——重度用户早期日期可能已被截断，累计天数可能低于真实历史。TotalSecs/Completed 永久保留，所以**累计时长/轮数精确**。因此文案只说「一共 N 天」（基于留存记录），不说「历史全部天数」，tooltip 亦不承诺完整性。1000 条边界下的聚合正确性纳入测试。

### 7.3 为什么不新增持久化字段（依据）

1. **架构先例**：TodaySecs/TodayRounds 本来就不落盘，每次快照从 Records 重算 [C1]——周/月/天数是同一逻辑的日期参数化，遵循既有模式，不是新发明。
2. **数据完备**：每条 Record 带 RFC3339 Date [C2]，周/月/天数可完全重建，不丢信息；持久化副本反而引入两份数据不一致的风险。
3. **迁移成本**：新增持久化字段要过 newAquarium 校验链与旧存档兼容逻辑 [C7]，且加重 D3 导出格式的版本兼容负担。
4. **性能可接受**：1000 条线性扫描是今日重算已在跑的开销量级 [C1]，周/月聚合同阶。

### 7.4 UI 设计【Q1/Q3 已定】

- **第一屏（默认可见，不改）**：底部统计区「今天的小积累」三格（今天分钟/今天轮数/朋友数）保持现状——它就是「今日」层。
- **第二屏（新增，默认折叠）**：新增 `details` 折叠区「**这段时间**」，位于「专注日记」折叠区之前。展开后自上而下：

  1. 本周专注（分钟 · 轮数）+ 本周有专注的天数
  2. 本月专注（分钟 · 轮数）
  3. 一起度过的：累计时长（沿用「已经一起度过 X 分钟，完成 N 轮专注」句式 [C12]）+ 一共 N 天
  4. 图鉴：X / 15，下一行最近到访的朋友
  5. 成长：当前称号 · 下一阶段提示（沿用 growth-label / next-growth 现有句式 [C5]）
  6. 尾注一行：「这些数字只保存在你的电脑上。」（呼应官网隐私承诺 [F11]）
- **为什么折叠而非直接铺开**：护栏要求「新增机制默认不可见、由用户主动发现」；`details` 是仓库已有交互模式（专注日记），零新交互成本 [C9]；统计是低频回看，不应挤占第一屏的「今天」与海底画面。
- **挂件模式：不显示统计**【Q3】：compact 模式本来就把整个底部统计区隐藏（`display:none`）[C11]。新增回顾面板落在 bottom-grid / details.journal 容器内，两者已在挂件模式隐藏，不破坏挂件布局 [T2]。

### 7.5 空态设计

- **全新用户（0 条记录）**：面板折叠区标题下显示「完成第一轮，这里开始有故事。」（对齐现有空态「你的海底，正在等待第一个故事。」句式 [C12]）；展开后各指标不显示 0 值表格，只显示一句引导 + 尾注。
- **有历史、本周尚无专注**：本周一行显示「本周还没有，不打紧，随时开始。」——不催促、不对比。
- **永不显示的形态**：红色/橙色告警色、「落后/错过/断掉」字样、与他人的对比、目标进度百分比条。

### 8.1 导出格式设计

- **形态**：单文件 JSON，人类可读。
- **顶层结构**：`{ "version": 1, "app": "little-reef", "exportedAt": "<RFC3339>", "aquarium": { …存档内容… } }`。带版本壳而非裸 aquarium.json 的理由：裸文件无法区分「存档」与「任意 JSON」，无法承载未来格式演进；revision 只是前端丢弃过期快照的新鲜度戳（app.js:54）、与数据迁移无关 [T5]——独立 version 壳与 revision 解耦。
- **aquarium 字段集合 = Snapshot 全量**：{revision, preferences, session, completed, totalSecs, todaySecs, todayRounds, records, visitors, lastVisitor, notice, fedSession, nowMs}——aquarium.json 本身就是 `snapshotLocked()` 的直接 marshal [T5]，导出复用 `saveLocked` 序列化段 [T4]。
- **瞬态字段处理【Q8】**：导出时原样保留；导入时忽略 todaySecs/todayRounds/nowMs，由导入后的首个快照按当天重算。
- **进行中会话**：不做导出前归一化——`newAquarium` 加载时本就强制 running→paused、清空 LastVisitor [C7][T4]，导入路径复用同一处理。
- **往返无损定义**：同版本内「导出→导入→再导出」byte 级等价——Go `json.Marshal` 键序稳定 [T5]；跨版本只承诺字段级语义等价（未知字段静默忽略、缺字段取零值 [T5]）。
- **导入校验顺序**：① JSON 可解析 → ② 顶层字段识别 → ③ aquarium 内容过 newAquarium 校验链 [C7][T4] → ④ 全部通过后才写入。任一步失败：**当前存档零改动**。错误文案复用现有基色。
- **失败回滚**：写入走既有 change() 模式——保存失败恢复 previous state 并报错 [C7]。
- **版本演进**：version 2+ 出现时旧版可导入则导入、不可导入则明确报「这是更新版本的存档，需要先升级小海底」。

### 8.2 边界场景

| 场景 | 行为 | 文案（过护栏） |
|-|-|-|
| 旧版本存档（v0.3 时期直接拷贝的 aquarium.json） | 可导入：加载对未知/缺字段静默容忍 [T5]；裸 aquarium.json 与带壳文件两者都接受，按「有无 version/app 壳字段」分流识别 | 「这是小海底的存档，已安全导入。」 |
| 损坏文件 / 非 JSON | 校验第①②步失败，零改动 | 「这个文件不是小海底的存档，什么都没有改动。」 |
| 内容字段越界（如负数时长） | 校验第③步失败，零改动 | 「存档内容有问题，没有导入。你的海底保持原样。」 |
| 更新版本的存档 | 拒绝导入 | 「这是更新版本的存档，先把小海底升级到最新版。」 |
| 导入会覆盖现有数据 | 导入前确认弹层 | 「导入会替换现在的海底。建议先导出一份当前存档。」 |

### 8.3 UX 设计【Q4】

- **入口**：设置对话框现有「检查更新 / 问题反馈」之后新增一节「**备份与恢复**」，两个按钮：「导出存档…」「导入存档…」[C10]。
- **成功文案**：导出「存档已保存到 <文件名>，收好它，随时可以恢复。」；导入「海底回来了，一切如初。」
- **文件对话框**：mygo v0.6.0 的 `Dialog.Save` / `Dialog.Open`（darwin/windows/linux 三端有后端实现 [T4]）——仓库此前仅用过 `Shell.OpenExternal`，首次接入需真机冒烟。浏览器模式【Q9】：导出=触发文件下载、导入=文件选择 input。
