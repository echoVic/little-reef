# 背景音换成真实录音 · 设计

- 日期：2026-10-11
- 状态：待评审
- 分支：`feat/real-ambience-recordings`

## 背景

20 种背景音目前全部由 `web/audio.js` 实时合成：随机噪声经一阶滤波，再乘固定周期的正弦起伏，每条 18 秒循环。听起来不真实，原因主要有：

- 起伏周期固定（海浪、风都是 9 秒一个来回），很快能听出规律；
- 鸟鸣、蝉、虫鸣、气泡都是纯正弦扫频，像电子提示音；
- 事件位置每 18 秒重复，例如雷雨里的三声雷每次都在同一时间点；
- 雨声没有雨滴，只有一层嘶声；咖啡馆人声、车流本来就很难靠合成做像。

用户反馈：“当前这些白噪音不真实。”

## 目标

除粉噪外的 19 种声音换成真实的实地录音，听感接近真实环境。开关、音量、淡入淡出、专注时自动播放、完成提示音等交互保持不变。

## 成功标准

1. 19 种声音都来自 CC0 实地录音；粉噪仍为实时合成。
2. 循环听不出接缝、不断音；时钟、木鱼的节奏在接缝处不乱；窗口收进托盘后持续播放。
3. 每条录音的响度与它替换的合成声音一致（±1 LU），真峰值不超过 −1 dBTP。
4. `web/sounds/` 总计约 25 MB，上限 30 MB。
5. 用户试听通过；不满意的条目从备选中替换。
6. Go 测试全部通过；浏览器模式下 20 种声音都能解码播放，控制台无报错。

## 不做的事

- 不改声音列表：ID、名称、顺序、Go 端偏好校验都不变。
- 不做随机片段拼接或其他“永不重复”的生成方式。
- 不做多种声音叠加混音。
- Linux 缺少 MP3 解码插件时，不回退到旧的合成声音，只给出提示。

## 素材

### 来源与授权

- 只用 Freesound 上 CC0 1.0 授权的录音。CC0 不要求署名，仍在 `THIRD_PARTY_NOTICES.txt` 列出每条录音的标题、作者、链接和许可。
- 源文件取 Freesound 公开的高码率试听版（OGG Vorbis，约 192 kbps，保留原始采样率，免登录）。原始文件需登录下载，以后可替换。

### 挑选规则

- 优先下载量和评分高、44.1 kHz 以上立体声、时长足以截出干净片段的录音。
- 用频谱图和响度统计排除：削波、麦克风风噪、电流哼声、能听清内容的人声，以及喇叭、警笛、关门等突兀事件。
- 每种另备两条候选，以注释记在构建脚本的表里，试听后直接替换。

## 处理与打包

### `build-sounds.sh`

放在仓库根目录，与 `package-macos.sh` 并列，只在更换录音时运行，依赖 ffmpeg（含 libmp3lame）和网络。平时构建和运行都不需要它。

- 顶部一张表：声音 ID、Freesound 编号、试听版地址、截取起点、时长、目标响度。
- 每条录音的步骤：
  1. 下载到 `${TMPDIR:-/tmp}/little-reef-sounds/`，已下载的跳过；
  2. 按起点和时长截取；
  3. 测量整体响度，线性增益到目标值；
  4. 真峰值超过 −1 dBTP 时加柔和限幅；
  5. 编码为 MP3（LAME VBR，默认 `-q:a 2`），保留源文件的采样率和声道数，写入 `web/sounds/<id>.mp3`；
  6. 复测响度与真峰值，打印结果。
- 木鱼：取真实单击采样，按周期 L = N × 1.35 秒排列 N 下，每下的时间偏移不超过 ±25 毫秒、力度起伏不超过 ±15%，随机数用固定种子。排好的序列按周期 L 重复，覆盖接缝处的交叉淡化区，循环时内容完全一致。
- 超出 30 MB 时，依次缩短事件型片段，或把编码质量降到 `-q:a 3`。

### 嵌入

生成的 MP3 直接提交进 git，不用 Git LFS。现有的 `//go:embed web` 会把它们打进程序，播放时不联网。

## 播放（`web/audio.js`）

### 接口

`Soundscape` 对外不变：`unlock`、`set(playing, sound, volume)`、`chime`、`dispose`。`app.js` 与 Go 端不改。

### 加载与循环

1. `fetch("sounds/<id>.mp3")`，再用 `decodeAudioData` 解码。
2. 在解码后的缓冲区里原地做接缝：从 `start` 秒起取循环长度 `loop`，把 `[start + loop, start + loop + fade)` 这一段与 `[start, start + fade)` 做等功率交叉淡化（前者淡出、后者淡入），结果写回前者。
3. 设置 `loopStart = start + fade`、`loopEnd = start + loop + fade`，用 `AudioBufferSourceNode` 的原生循环播放，不依赖定时器。
4. 默认值：`start` 为 0.25 秒（避开编码器在开头补的静音），`fade` 为 3 秒，`loop` 取最大值，使 `loopEnd`（即 `start + loop + fade`）落在距文件末尾 0.25 秒处。
5. 时钟、木鱼、音乐盒在提示表里写明 `start`、`loop`、`fade`：
   - 时钟、木鱼的 `loop` 取整数拍，`start` 落在两下敲击之间的空隙，`fade` 约 0.15 秒，交叉淡化只发生在空隙里；
   - 音乐盒的 `loop` 取整首，在曲尾余音处衔接。

### 起播位置

音乐盒从曲头开始；其余声音每次从循环区间内的随机位置开始。

### 缓存与竞态

- 按声音缓存解码的 Promise，只保留最近两种；每种解码后约占 20–35 MB 内存。
- 加载失败的 Promise 从缓存移除，下次可重试。
- 沿用现有的 `sequence` 校验，加载完成后再校验一次，过期的请求不出声。

### 错误处理

读取或解码失败时，调用 `onStatus("这段声音暂时无法播放，计时不受影响", true)`，界面弹出提示，计时照常。

### 粉噪与旧代码

粉噪保留原合成算法（18 秒），改用新的接缝处理。其余 19 种的合成代码删除。

## 测试与验证

- Go 测试：每种声音（粉噪除外）在嵌入的 `web/sounds/` 中都有非空的 MP3 文件。
- 浏览器模式自动检查（一次性脚本，不提交）：
  - 逐个加载 20 种声音，确认解码成功、循环区间合理；
  - 接缝处的样本跳变不超过片段内的典型值，接缝前后短窗 RMS 连续；
  - 点遍界面上的声音按钮，控制台无报错。
- 响度：脚本复测每条在目标 ±1 LU 内，真峰值不超过 −1 dBTP。
- 体积：统计 `web/sounds/` 总大小，不超过 30 MB。
- 人工：用户在桌面版逐个试听，不满意的从备选替换后重跑脚本。

## 风险

- 实现者无法试听，只能靠数据挑选和检查，最终以用户试听为准。
- Linux 的 WebKitGTK 缺少 MP3 解码插件时，19 种录音无法播放（粉噪仍可用）：README 注明依赖，界面给出提示。
- 用的是试听版而非原始文件，音质略低，对环境声影响很小；以后可以用 Freesound 账号下载原始文件替换。
- 内存：每种声音解码后约 20–35 MB，最多同时缓存两种。
